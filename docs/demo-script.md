# Creative Minds 现场三分钟演示脚本

正式 DoraHacks 视频必须控制在 1.5–2 分钟，请使用 [1 分 50 秒提交脚本](submission-pack.md#1-分-50-秒提交视频脚本)。本文件用于现场较完整演示。

## 演示前检查

1. 在 `.env.local` 配置 `MINDS_BUILDER_API_KEY`；有多个 Mind 时配置 `MINDS_MIND_ID`。
2. 至少配置一个 `CREATOR_MIND_RSS_FEEDS`；如有 X 开发者权限，再配置 `X_BEARER_TOKEN`。
3. 运行 `pnpm test && pnpm typecheck && pnpm build`，确认关键旅程和生产构建通过。
4. 用 `pnpm dev` 启动并打开 `http://localhost:3000`。

## 三分钟主线

### 1. 先讲痛点（20 秒）

“创作者不缺生成文案，缺的是可信选题、证据边界、最后决定权，以及发布之后真正能积累的经验。”

### 2. 证明 Mind 参与选题（35 秒）

- 保存创作者定位、目标受众和表达方式。
- 点击“验证核心 Mind”，指出页面显示真实 Mind 名称。
- 点击“运行真实来源”。
- 展开雷达中的“核心 Mind 决策”，展示排序理由、会话别名和决策标识。

评委要看到：数据由应用采集，优先级由 Mind 根据创作者基线判断。

### 3. 证明 Mind 参与平台表达（45 秒）

- 在真实信号旁先选择 X 或小红书，再点击“生成版本”。
- 说明系统先在本地锁定证据包，再只调用一次 Mind 生成所选平台内容，不会预生成其他平台。
- 进入“内容草稿”，指出支持项、未知项、来源链接和证据版本。
- 展示 X 的完整句与 280 字符校验，或小红书的标题、正文、标签、封面文案和图片建议。
- 展示来源引用、`usedMemoryIds` 和 `memoryInfluence`；超长内容由 Mind 重写，绝不硬截断。
- 备用演示：连续两次自动修订仍失败时，展示完整原稿和人工编辑区，保存后重新校验。

### 4. 证明人始终掌握发布权（30 秒）

- 填写审核原因并批准。
- 指出状态只是“已批准未发布”，系统没有 X 发布按钮。
- 说明创作者在 X 外部手工发布，再把实际链接和最终文案带回工作台。

### 5. 证明 Mind 形成可控学习（35 秒）

- 手工填写部分指标，故意留空“收藏”。
- 指出页面显示“未提供”，不会把缺失值算作 0，也不会计算不完整互动率。
- 点击“让核心 Mind 复盘”。
- 展示 Mind 基于实际发布文本和指标提出的可验证假设；现场改写后接受，说明 SQLite 保留审计源，并向稳定 Mind 会话提交 `MEMORY_COMMIT`。
- 展示第二轮平台草稿引用该记忆 ID，以及记忆具体改变了哪项表达决策。
- 强调证明页读取的是“第一轮发布与学习 → 第二轮使用”，不会把同一轮重复调用算作成长。

评委要看到：Mind 不是聊天装饰，而是贯穿选题、表达和学习；每次判断都有来源与人工控制。

### 6. 一屏核验证据（15 秒）

- 打开“比赛证明”，确认选题、平台表达、学习、自主跟进、记忆因果五项都显示“已验证”。
- 点击“下载 JSON 证据”；说明系统会把演示或缺失链路明确标出来，不能拼接无关记录冒充闭环。
- 展示 3–5 名真实创作者的两轮测试统计；这部分必须由真实使用产生，不能预置。

## 无 X 权限的备用路径

点击“运行演示”可以走完平台草稿、审核、手工发布关联与学习闭环，但全部保留演示标记。正式运行不会静默回退演示数据；演示数据和 Recorded Mind 不能冒充真实调用。

## 现场失败处理

- Mind 不可用：展示中文状态，不生成正式 Mind 草稿；切换演示流程说明产品安全边界。
- 单个 RSS 失败：展示该来源警告，其余来源继续。
- X 无 Token 或额度：展示官方 API 未配置/不可用提示，绝不抓取网页绕过限制。
- Horizon 或 Mind 超时：在运行记录中显示失败阶段，点击“从失败阶段重试”；已完成采集不会重跑。
- 指标不全：按未知处理，避免伪造精确结论。
