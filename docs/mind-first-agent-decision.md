# X News Toolbox：Mind 自动运行方案决策笔记

## 一、核心结论

X News Toolbox 适合从“需要创作者逐页操作的工作台”，调整为：

> **由 Mind 持续自动运行，工作台只负责首次配置、查看结果和人工审核。**

这比让用户反复进入信息来源、雷达、结果、草稿等页面操作，更符合创作者的真实需求，也更符合 Creative Minds Jam 对持续性 Agent、后台执行和 Mind 核心作用的强调。

工作台不需要完全删除，而应当从复杂的操作后台缩减成简单的“内容收件箱”。

---

## 二、从第一性原理出发

### 创作者真正需要的结果

创作者通常并不关心 Agent 内部执行了多少步骤。他们真正需要的是：

1. 自动找到与自己定位相关的信息；
2. 从大量信息中筛选值得创作的主题；
3. 根据自己的风格和受众形成创作角度；
4. 生成适合目标平台的文案；
5. 保留来源链接和事实依据；
6. 在发布前进行人工确认；
7. 长期记住自己的偏好和审核反馈。

因此，产品最理想的交付不是一个复杂后台，而是：

> **每天自动向创作者提供几条值得发布、已经适配平台、保留事实来源的候选文案。**

### 当前工作台的问题

当前流程需要用户分别操作信息来源、雷达、结果、风格、草稿和连接设置。虽然功能完整，但用户需要理解整个系统如何运作，使用成本较高。

如果每次运行都需要创作者手动完成多个步骤，它更像“带 AI 功能的软件工具”，而不是能够持续替创作者工作的 Agent。

---

## 三、从比赛角度出发

Creative Minds Jam 要求 Minds 成为参赛作品的重要组成部分。比赛官网强调的能力包括：

- 持续身份与记忆；
- 专门的技能和工具；
- 后台运行；
- 自动执行工作流；
- 根据历史互动不断进化；
- 解决创作者在内容生产、跨平台复用、增长和管理方面的问题。

X News Toolbox 如果只在生成草稿时调用一次 Mind，虽然符合“使用了 Minds”，但 Mind 的核心价值不够突出。

如果改成由 Mind 主动调度信息发现、内容判断和文案生成，就能更清楚地证明：

> Mind 不是一个普通的改写接口，而是创作者长期使用的内容决策 Agent。

比赛项目可以定位为：

> **A persistent, human-in-the-loop content intelligence agent that continuously discovers opportunities and prepares platform-ready drafts for creators.**

中文表述：

> **一个持续运行、保留人工审核的创作者内容情报与跨平台文案 Agent。**

比赛官方说明：[Creative Minds Jam](https://creativemindsjam.com/)

---

## 四、推荐的系统分工

| 组件 | 职责 |
| --- | --- |
| Mind | 保存创作者定位、目标、风格和历史反馈；决定什么值得写、从什么角度写，并调度完整任务 |
| Horizon | 扫描、聚合、去重、评分和补充信息来源 |
| 本地服务 | 提供来源读取、数据保存、平台规则校验和任务状态接口 |
| 平台适配器 | 检查平台字符、链接、格式和必要字段 |
| 精简工作台 | 首次配置、显示运行状态、查看候选文案和人工审核 |
| 创作者 | 决定采用、修改、拒绝或发布，不把最终控制权交给系统 |

Mind 是决策层，Horizon 是信息雷达，本地服务是执行层，创作者是最终责任人。

---

## 五、自动运行流程

```text
定时任务或用户一句话触发
        ↓
Mind 读取创作者定位、受众、历史反馈和目标平台
        ↓
Mind 调用 Horizon 扫描最近一段时间的信息
        ↓
Horizon 返回去重、评分并带来源的信息候选
        ↓
Mind 判断哪些内容值得创作
        ↓
Mind 根据创作者风格生成所选平台文案
        ↓
本地平台规则进行长度、链接和格式校验
        ↓
候选文案进入工作台“今日内容”
        ↓
创作者审核、修改、复制或拒绝
        ↓
审核反馈进入 Mind 的长期记忆
```

默认不自动发布。只有后续明确接入官方平台 API、完成权限说明并得到用户授权后，才考虑增加发布能力。

## 六、创作者第一次需要配置的内容

用户只需在第一次使用时填写：

- 创作者定位；
- 目标受众；
- 关注的主题；
- 信息来源；
- 默认输出平台；
- 每次输出数量；
- 扫描时间范围；
- 自动运行时间；
- Mind ID 和 Minds API Key；
- Horizon 使用的 AI 服务配置；
- 必要的平台 API 凭据。

完成首次设置后，日常不再要求用户逐页启动任务。

## 七、精简后的工作台

### 1. 今日内容

显示 Mind 自动生成的候选内容，包括：

- 主题；
- 推荐理由；
- 创作角度；
- 平台文案；
- 来源链接；
- 风险提示；
- 复制、修改、采用和拒绝按钮。

### 2. 运行状态

显示：

- 等待运行；
- 正在扫描；
- 正在分析；
- 正在生成；
- 等待审核；
- 已完成；
- 运行失败及原因。

### 3. 设置

集中配置：

- Mind；
- Horizon；
- 信息来源；
- 默认平台；
- 输出数量；
- 运行时间；
- API 凭据。

原有的雷达、来源、风格、草稿和结果能力可以继续保留在系统内部，但不需要全部作为一级页面暴露给普通用户。

## 八、可以直接交给 Mind 的任务说明

```text
你是 X News Toolbox 的创作者内容决策 Agent。

你的目标是持续帮助创作者发现值得表达的信息，并生成符合其定位、受众、风格和目标平台的候选文案。

每次运行时：
1. 读取创作者的定位、目标受众、关注主题、历史审核反馈和默认平台；
2. 调用信息雷达，扫描最近 24 小时的已配置来源；
3. 对信息进行筛选，只保留与创作者定位相关且来源可追溯的内容；
4. 选择最值得创作的 3 条信息，并解释推荐理由；
5. 为用户选择的平台生成文案，不要同时生成所有平台版本；
6. 保留来源链接，不得编造材料中不存在的事实、数字或人物观点；
7. 标注存在冲突、无法确认或需要人工核实的信息；
8. 将结果发送到工作台等待人工审核；
9. 未经用户明确确认，不得自动发布、回复、点赞或关注；
10. 根据创作者的采用、修改和拒绝记录，更新后续选题与表达偏好。
```

## 九、Mind 调用本地能力的技术前提

如果 Mind 运行在云端，它不能直接访问用户电脑上的 `localhost:3000`。

需要选择以下方式之一：

### 方案 A：部署 Tool API（推荐用于正式比赛演示）

把必要能力包装成带身份验证的 HTTPS 接口，例如：

- `POST /api/agent/runs`：启动雷达任务；
- `GET /api/agent/runs/:id`：读取任务状态；
- `GET /api/agent/signals`：读取候选信息；
- `POST /api/agent/drafts`：保存 Mind 生成的候选文案；
- `POST /api/agent/feedback`：提交采用、修改或拒绝反馈。

Mind 通过 HTTPS 调用这些接口，工作台只显示结果。

### 方案 B：制作 Mind Skill

把工作流程、输入字段、输出格式和工具调用规则制作成一个 Mind Skill，让 Mind 知道何时扫描、如何筛选、如何生成和如何等待人工审核。

### 推荐组合

> **Mind Skill 负责流程和判断，HTTPS Tool API 负责执行和数据。**

这样既能体现 Mind 的持续身份和自主决策，也能复用现有 Horizon、SQLite、来源管理和平台校验能力。

## 十、安全边界

- 不允许 Mind 自行更换信息来源；
- 不允许使用未经授权的 X 账号数据；
- 不允许把 API Key 写进对话或返回结果；
- 不允许在缺少来源证据时生成确定性结论；
- 不允许默认自动发布；
- 每次结果必须保存来源、生成时间和使用的规则版本；
- 用户可以暂停自动运行并删除自己的运行记录；
- 对外开放的 Tool API 必须有身份验证、请求限流和操作审计。

---

## 十一、建议的比赛演示

1. 展示创作者第一次配置自己的定位、来源和目标平台；
2. 展示 Mind 已经记住创作者的风格和历史偏好；
3. 触发一次自动任务，或者展示定时任务自动开始；
4. 显示“扫描中 → 分析中 → 生成中 → 等待审核”；
5. 展示 Mind 为什么选择其中一条信息；
6. 展示带来源、风险提示和平台格式校验的候选文案；
7. 创作者修改或拒绝文案；
8. 展示 Mind 如何把反馈用于下一次任务。

演示重点不是页面数量，而是证明：

> **这个 Agent 在创作者不操作工作台时仍能持续工作，并且会根据创作者的反馈变得更了解他。**

---

## 十二、最终建议

采用以下产品方向：

> **Mind 主动运行 + Horizon 信息雷达 + 精简工作台审核 + 人工决定发布。**

保留现有项目作为 Agent 的执行和审核基础，不必推倒重做。下一阶段应优先实现：

1. 明确 Mind Skill；
2. 提供最小 HTTPS Tool API；
3. 将工作台缩减成今日内容、运行状态和设置；
4. 建立定时运行和失败重试；
5. 保留人工审核与来源追踪；
6. 用一次完整的真实数据流程进行比赛验收。
